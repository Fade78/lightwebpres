lightwebpres · colour themes

Named palettes, ready to use

Every card is a REAL card: the same parser, the same renderer and the same stylesheet a build uses, in an iframe so the sheet's viewport-relative sizes resolve against the preview. Each theme sets twenty-one custom properties — six palette colours, six that decide how bold renders inside a fact-box, and nine translucent overlays that follow the background's polarity. This page is generated from the THEMES table embedded in the executable — see specifications.md §9.5.

The six palette variables name a role, not a colour. They were --yellow, --dark, --grey, --light and --green until v0.12.0, after the values they happened to hold in the very first theme. Those names lied as soon as a theme moved away from it: on an already-yellow page --yellow held a dark olive, or the marker would have been invisible; on a dark theme --light held a near-black while --dark held the text colour. A name you have to un-learn before you can use it is worth no more than no name, so each variable now carries its own. No aliases were kept — audit reports any old name left in your own rules.
