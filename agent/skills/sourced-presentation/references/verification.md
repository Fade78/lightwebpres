# Revision and handoff checks

Use to bound a correction, move material, verify the result or deliver it.
A passed check applies to the version and perimeter actually examined.

## Change triggers

| Change | Reopen |
|---|---|
| Fact, causal link, scope or quantity | Source, derivation, long-form passage and every dependent card. |
| Editorial intention or thesis | Evidence selection, reasoning, decisive objections, card selection and the article–presentation connection. |
| Wording or emphasis | Whole affected unit, explanation before conclusion, all short reading paths and agreement with the long. |
| Quotation or translation | Original wording, context, status, reuse limits and other uses of that source. |
| Discovered defect | Enumerate and inspect the same defect class across the relevant corpus. |
| Unit added, removed or moved | Preserved contributions, transitions, inventories, counts, links and ordering claims. |
| Heading, slug, name or numbering | References and anchors in both short and long forms. |
| Editorial specification | Existing affected units, not only future writing. |
| Tool or format | Fields retained, ignored or defaulted; actual output and relevant options, when testing is authorized. |

Read the current files first. A past completion report is not the current
state. Protect pre-existing work, distinguish discussion from production,
and do not expand scope silently. Record unresolved items and what still
needs checking; a repaired pilot does not certify the rest.

## Reading and verification record

1. **Article alone:** read continuously after edits. Does its own argument
   hold, with claims, inferences, value premises and pertinent objections
   distinguished? Check duplicated or stranded material and attribution;
   verify new claims against sources, not intended meaning.
2. **Each affected card:** test the explanation before its conclusion;
   then whole card, title–stake–conclusion and conclusion alone. What
   supported point deserves attention and should be remembered? Check actors,
   operations, interest, plausible objection, complete takeaway and scope.
3. **Sources without the draft:** revisit research axes and relevant findings,
   including null, contrary and unresolved results. Look for omissions or
   excess emphasis, not just agreement with selected sentences.
4. **Cards against article:** check every fact, figure, quotation, comparison
   and inference, including implications of prominent layers. Is each
   established in the long? Selection and reordering are allowed; stronger
   claims or missing material qualifications are not.
5. **Page and series:** walk the route and affected units. Check contributions,
   transitions, shared terminology, repeated sources, links, counts and
   references to positions. Reconcile content and runtime counting conventions.

Check the dominant intention as well: shared criteria without false
equivalence when comparing; evidence strength and open questions when
reviewing knowledge; explicit thesis, reasoning and decisive objections
when arguing. If the intention changes within a page, check that the
transition does not pass a recommendation off as an empirical finding.

Enumerate items before a judgment check. Search locates candidates; silence
does not prove completeness. Counts need a defined unit. For bulk changes,
compare the expected set with the actual set and inspect omissions, not
only successful replacements. Never narrow a check just to make it pass.

After edits, read the result against the unchanged material. Removing a
phrase can break a subject or comparison; removing repetition can create
contradiction. Check for duplicated sections before repairing individual
sentences. Valid markup is not a coherent explanation.

Check notes throughout their lifecycle: calls, definitions, local scope,
targets and the fact supported. Removing one call does not authorize
deleting a definition still used elsewhere. Prefer native format support;
custom wrappers can bypass reference handling and hide content loss.

Use an independent review as findings to examine. Verify each against
current text and sources; record fixed, already resolved or rejected items
with reasons. Agreement between reviewers is not independent evidence of a fact.

Report actual reading scope and access. Simulated reader reactions and
readability checks are not reception studies. One strong pilot, an author's
approval of an example or a clean syntax check does not validate unread units.

## Tools and delivery

- Follow the environment's tool source and the author's permissions.
  Where PATH executables are required, use them; do not download or pin
  another version to draft. Inspect the current contract before guessing flags.
- Keep editorial, presentation and publication actions distinct. A wording
  request does not authorize styling, navigation or publication changes.
  Respect a no-build instruction; explain which output checks remain unperformed.
- When an output check is authorized, inspect the actual artifact with the
  relevant options: text, links, retained fields, defaults and requested
  variants. An older preview or clean input does not certify new output.
- Keep generated files and caches in their authorized workspace. Do not
  replace existing deliveries without checking identity and permission.
  A technical pass establishes format behavior, not reader understanding.
- Inspect status and diff before handoff. Use the prescribed delivery and
  registration process; verify the delivered bytes and availability. A
  local copy alone may not complete the required handoff.
- Distinguish proposed, delivered, installed and published states. Respect
  standing authorizations as well as task-specific ones; do not infer
  installation, commit, tag or publication from a request to discuss or export.
- Keep working notes in the author's working language. Record evidence
  boundaries, decisions and the next step so another session can continue
  without reconstructing intent. Do not leak internal notes into reader-facing text.
- Date corrections after publication and preserve the trace of what changed
  and why. Verify the actual state before claiming completion; report partial
  success, expected exclusions and remaining uncertainty accurately.
